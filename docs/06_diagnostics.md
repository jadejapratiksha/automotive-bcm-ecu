6. Diagnostics

6.1 Purpose

This document describes the diagnostic functionality implemented in the completed BCM firmware.

The current implementation is intentionally simpler than a production UDS diagnostic stack.

6.2 Architecture

BatteryMonitor / VehicleStateManager

The Fault Manager is the source of truth for active conditions.

The Diagnostic Manager converts active fault bits into DTC bits and detects newly active conditions.

The Diagnostic Manager rebuilds the DTC mask from the current fault state every cycle.

DTCs are not latched or stored in non-volatile memory.

6.6 DTC Query API

The diagnostic service exposes functions conceptually equivalent to:

bool DiagnosticManager_IsDTCActive(diagnostic_code_t dtc);
uint32_t DiagnosticManager_GetDTCMask(void);

Invalid or unsupported DTC values shall not corrupt the internal mask.

6.8 Ring Buffer

The event logger uses a 16-entry ring buffer.

Behavior:

Fixed memory allocation

FIFO ordering

Oldest entry overwritten when full

Separate total event count

This is appropriate for an embedded project because memory usage is deterministic.

6.9 CAN Visibility

The periodic BCM_STATUS frame transmits the Fault Manager mask in bytes 4–7.

The frame does not currently transmit a standardized UDS DTC response.

Because the implemented DTC mapping is one-to-one with the fault bits, the masks are numerically identical today, but they represent different concepts:

Fault mask: current internal source conditions

DTC mask: diagnostic representation of those conditions
